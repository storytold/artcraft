# fake-storyteller-web

An in-memory stand-in for the `storyteller-web` API, so the webapp can be run
and tested without a backend.

It has **no database, no cache, no object storage, and no third-party clients**.
There is no configuration that makes it talk to any of those, and no code path
that could. It is a separate Nx project that is never built into, imported by,
or deployed alongside anything that reaches production.

```
nx serve fake-storyteller-web         # http://localhost:12345
nx serve artcraft-webapp --mode fake  # http://localhost:4201, pointed at the fake
```

Log in as `localdev1` / `localdev1pass`.

`--mode fake` loads `apps/artcraft-webapp/.env.fake`, which sets
`VITE_DEV_API_HOST=http://localhost:12345`. **Without it, `nx serve
artcraft-webapp` talks to production** — the dev server's `/v1` proxy forwards
to `api.storyteller.ai`, so local work reads and writes real data and spends
real credits. Nothing about that changed; the flag is how you opt out of it.

## Why this exists

The previous approach put development flags inside `storyteller-web` itself
(`DEV_FAKE_GENERATION`, a filesystem bucket backend, a CDN host override). That
works, but every one of those flags is a switch that exists in the production
binary, and the objection was fair: a flag that exists can be flipped.

Here, none of it exists. The behaviour lives in a different program, in a
different language, that production never builds.

## What it does

- **Stateful, in memory.** Uploads appear in the library, generations produce
  real media files, credits go down, folders and tags persist. Everything resets
  on restart, always to the same seeded fixture.
- **Serves its own media.** Uploaded and generated bytes are stored in memory and
  served from `/media/...`. Every `cdn_url` the API returns points back at this
  process, so images, video, meshes and splats load in the browser with no
  bucket and no proxy.
- **Resolves generations on a timer.** A submitted job sits `pending`, ticks its
  progress up, and lands in `complete_success` or `complete_failure` after
  `FAKE_API_RESOLVE_SECONDS` (default 6).
- **Fails loudly on gaps.** An unimplemented route returns a 501 whose body says
  `fake-storyteller-web does not implement ...`, rather than something that
  could be mistaken for a real backend error.

Endpoint coverage is everything the webapp's `@storyteller/api` clients call —
148 routes across session/auth, credits, billing, omni_gen, jobs, media files,
uploads, projects, folders, tags, prompts, characters, API keys and referral
codes.

## Prompt flags

Typing one of these into a prompt forces an outcome. They match the flags the
team already uses.

| Flag                                   | Effect                                                  |
|----------------------------------------|---------------------------------------------------------|
| `simulate_artcraft_failure [category]` | Fail after the normal delay                             |
| `test_artcraft_failure [category]`     | Alias of the above                                      |
| `artcraft_test_job_failure`            | Fail immediately, with no pending phase                 |
| `trigger_payment_failure`              | Reject the submission with a 402                        |
| `simulate_artcraft_slow [seconds]`     | Stay pending for the given number of seconds            |

`[category]` is any frontend failure category, for example
`simulate_artcraft_failure face_not_detected`. Omitted, it is
`generation_failed`. The full list is at `GET /__fake/state`.

## Control endpoints

These do not exist in the real API and are namespaced so that a dependency on
them is obvious.

| Endpoint                | Purpose                                              |
|-------------------------|------------------------------------------------------|
| `GET /__fake/state`     | Record counts, resolve delay, failure category list  |
| `POST /__fake/reset`    | Reset to the seeded fixture (logs everyone out)      |
| `POST /__fake/credits`  | Set the logged-in user's balance                     |
| `GET /_status`          | Health check, same path as the real backend          |

## Configuration

| Variable                   | Default     | Meaning                                  |
|----------------------------|-------------|------------------------------------------|
| `FAKE_API_PORT`            | `12345`     | Listen port                              |
| `FAKE_API_HOST`            | `127.0.0.1` | Listen address                           |
| `FAKE_API_PUBLIC_BASE_URL` | derived     | Origin embedded in generated media URLs  |
| `FAKE_API_RESOLVE_SECONDS` | `6`         | How long a generation stays pending      |
| `FAKE_API_DEMO_CREDITS`    | `100000`    | Credits granted to the seeded user       |

## Testing

```
nx run fake-storyteller-web:smoke        # boots the server and drives ~50 assertions
nx run fake-storyteller-web:typecheck
```

The smoke test covers login, the seeded library, media serving, the model
catalogue, cost, a full generation lifecycle, the failure and payment triggers,
credit deduction, upload round-tripping, and folders and tags. It exits non-zero
on the first failure, so it is usable as a CI gate.

## Implementation notes

**No dependencies and no build step.** It runs on `node:http` with Node's native
TypeScript stripping (`node src/main.ts`, Node 22.6+). Nothing is installed and
nothing is compiled, so it starts instantly and works in a bare checkout.

Because Node strips types rather than compiling them, runtime code here must
stay *erasable*: no TS `enum`, no `namespace`, no parameter properties. Use
`const` objects and union types instead. The server failing to boot is the
immediate signal if this is violated.

**Response shapes follow the Rust backend, not `@storyteller/api`.** This was a
deliberate call, and it is the most important thing to know before editing.

## Drift between `@storyteller/api` and the real backend

The suggestion that prompted this project was to depend on the frontend's API
package so the fake could not drift. That turns out to be only half possible:
the package is not currently an accurate description of the backend, so binding
responses to it would make the fake serve values the real API never sends, and
hide the very bugs it should surface.

So the fake mirrors the Rust structs, and `src/wire/contract_checks.ts` binds
the parts that *do* agree (`Visibility`, `JobStatus`) at compile time — if
either side changes those, `typecheck` fails.

The drift found while building this is worth fixing in the package itself:

| Where                                  | Drift                                                                                                  |
|----------------------------------------|--------------------------------------------------------------------------------------------------------|
| `enums/MediaFileClass`                 | Frontend has `animation`/`character`/`prop`/`scene`; backend sends `dimensional`/`mesh`/`splat`/`project` |
| `enums/MediaFileType`                  | Frontend has `mmd`/`scene`/`none` and is missing every concrete type sent (`jpg`, `png`, `mp4`, `spz`, `ply`, `scene_json`, ...) |
| `models/MediaFile.media_links`         | Declares `thumbnail_template`; backend sends `maybe_thumbnail_template`, and also `maybe_video_previews`  |
| `models/MediaFile.maybe_creator_user`  | Named `maybe_creator` on `/list`, `/list_featured`, `/search_*`; absent entirely on `/list/user/:username` |
| `models/MediaFile.maybe_creator_user`  | Typed `UserInfo`; backend sends the much smaller `UserDetailsLight`                                       |
| `models/MediaFile.origin*`             | Declared non-optional, but not sent at all by `/file/:token`, `/batch`, `/search_*`, `/mesh/list`, `/splat/list`, `/project/list` |
| `JobsApi.ListJobs()`                   | Calls `/v1/jobs/batch` with no `tokens` parameter, which the real backend rejects with a 400 — so this call always fails in production |
| `OmniGenApi` image requests            | Sends `horizontal_angle`/`vertical_angle`/`zoom`; backend reads `adjust_*`, so the angle controls are silently dropped |
| `OmniGenVideoGenerateResponse`         | Omits `all_job_tokens`, so batched video jobs beyond the first are never polled                          |
| `JobsApi.GetPreviewStatusByJobToken`   | Reads `response.data`; the envelope is `{success, state}`, so it is always `undefined`                    |

Where the fake had to choose, it follows the backend — except for
`/v1/jobs/batch`, where it returns an empty list instead of a 400 so that the
client's own call pattern works.

## Layout

```
src/
  main.ts              server bootstrap, CORS, 501 handling
  config.ts            environment configuration
  auth.ts              sessions, cookies, the `session` header
  http/                router, request context, multipart parser, responses
  state/               records, the store, seeding, media and asset creation
  wire/                response builders, one per real response shape
  generation/          model catalogue, cost, submission, prompt flags, resolver
  routes/              one module per API area
scripts/smoke_test.mjs end-to-end test
```
