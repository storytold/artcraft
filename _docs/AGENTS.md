# Agent and development documentation

Preserve the root's operative rules and the code owners' contextual instructions.
Keep explanatory methodology separate from concise commands that an agent must follow.
Label proposals, optional workflows and observed implementation facts distinctly.

When editing agent guidance, map each rule to the failure it prevents and its actual
test or manual check. Do not invent a guard or imply documentation enforces isolation.
Check moved links, root and nested discovery, and each `CLAUDE.md` symlink target/mode.
Retain existing conventions unless a deliberate adoption choice changes them.
Avoid claims that agents automatically review every PR or that outside contribution
acceptance follows from repository visibility. Maintainers own review and adoption.
